Only the image is required. The examples use a native install. In Docker, pass the same flags after `scan` as shown in [Run with Docker](../docker/).

## Image only

Runs hardening checks on the image. For userland CVEs, Trowl reads the package database or falls back to supported binary fingerprints.

```sh
trowl scan core-image-minimal-qemux86-64.rootfs.ext4.zst -o report
```

## Image and SBOM

Adds package versions and any CVE statuses recorded by Yocto. Trowl also checks declared files against the image. See [SBOM analysis](../../features/sbom/).

```sh
trowl scan core-image-minimal-qemux86-64.rootfs.ext4.zst \
  --sbom core-image-minimal-qemux86-64.rootfs.spdx.json \
  -o report
```

## Kernel VEX assessment

Uses the matching kernel source, config and shipped modules to assess whether vulnerable code is included. The SBOM remains optional. See [CVEs and VEX](../../features/cves-vex/).

```sh
trowl scan core-image-minimal-qemux86-64.rootfs.ext4.zst \
  --sbom core-image-minimal-qemux86-64.rootfs.spdx.json \
  --kernel-config kernel.config \
  --kernel-tree ~/src/linux-6.18.52 \
  -o report
```

## Yocto input paths

The [meta-trowl layer](../../integrations/yocto/) locates inputs and scans images automatically. For manual scans, use these paths relative to the build directory.

<div style={{ overflowX: 'auto' }}>

| Input | Location |
| --- | --- |
| Image | `tmp/deploy/images/<machine>/<image>-<machine>.rootfs.ext4` (or `.wic`, `.tar.zst`, `.squashfs`) |
| SBOM, SPDX 3.0 | `tmp/deploy/images/<machine>/<image>-<machine>.rootfs.spdx.json` |
| SBOM, SPDX 2.2 | `tmp/deploy/images/<machine>/<image>-<machine>.spdx.tar.zst` |
| Kernel `.config` | `.config` in the kernel build folder under `tmp/work/` |
| Kernel source | `tmp/work-shared/<machine>/kernel-source`, or a kernel.org checkout at the same release |

</div>

Omit `--kernel-config` when Trowl can read `/boot/config-*` or a config embedded with `CONFIG_IKCONFIG` from the image.

## Open the report

Open `report/index.html` directly or serve the report locally:

```sh
trowl view report  # http://127.0.0.1:8765
```

The sidebar groups results into Overview, Filesystems, Kernel, Binary, SBOM Analysis and CVEs. Kernel contains Config and Modules. Pages without data are disabled. SBOM Analysis requires `--sbom`.

The dashboard also works on any static host. See [Report output](../../reference/report/) for formats and sharing.
