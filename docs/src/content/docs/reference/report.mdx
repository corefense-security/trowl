Each scan writes a JSON report and a static HTML dashboard to the output folder. OpenVEX export is coming soon. The output location depends on how you run Trowl:

<div style={{ overflowX: 'auto' }}>

| Run | Output folder | Set with |
| --- | --- | --- |
| [Command line](../cli/#trowl-scan) | `./trowl-report/` by default | `-o DIR` or `--output DIR` |
| [Docker](../../getting-started/docker/#run-a-scan) | `~/trowl-out/report/` on the host in the example | `-o /out/report` with `~/trowl-out` mounted at `/out` |
| [Yocto](../../integrations/yocto/#additional-settings) | `${TOPDIR}/trowl/<image>/` by default | `TROWL_REPORT_DIR` sets the base folder in `local.conf` |

</div>

## Formats

| Format | Output |
| --- | --- |
| JSON | `report.json` with scan results |
| Static HTML | `index.html` with the dashboard in one file |
| OpenVEX | Coming soon |



## Static HTML dashboard

Each scan produces `index.html` with the dashboard and report data embedded. No template setup or external dependencies are needed.

Render it locally, or publish it as CI artifacts via GitHub Pages, Cloudflare Pages, S3:

```sh
trowl view ./trowl-report  # http://127.0.0.1:8765
```


## JSON report

`report.json` contains the same results shown in the dashboard. Read it in a text editor or process it with JSON tools and scripts. 

The top-level keys are:

| Key | Contents |
| --- | --- |
| `tool` | Trowl name and version |
| `image` | Path, detected format, file count and unpack notes |
| `summary` | Finding counts per check, ELF counts, scan time |
| `findings` | One entry per issue with `check`, `path`, `title`, `detail` and `evidence` |
| `binaries` | Hardening properties of every ELF file |
| `fstab` | Mount entries and missing flags |
| `kernel` | Config source, version, arch, baseline results, policy and modules |
| `sbom` | Components, presence status and the dependency graph. `null` without `--sbom` |
| `cves` | CVE rows with status, CVSS, KEV, EPSS, links and kernel assessment |
| `overview` | The AI summary if a model ran |
