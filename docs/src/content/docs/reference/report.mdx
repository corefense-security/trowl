Each scan writes a JSON report, a static HTML dashboard and an OpenVEX document to the output folder. The output location depends on how you run Trowl:

<div style={{ overflowX: 'auto' }}>

| Run | Output folder | Set with |
| --- | --- | --- |
| [Command line](../cli/#trowl-scan) | `./trowl-report/` by default | `-o DIR` or `--output DIR` |
| [Docker](../../getting-started/docker/#run-a-scan) | `~/trowl-out/report/` on the host in the example | `-o /out/report` with `~/trowl-out` mounted at `/out` |
| [Yocto](../../integrations/yocto/#additional-settings) | `${TOPDIR}/trowl/<image>/` by default | `TROWL_REPORT_DIR` sets the base folder in `local.conf` |

</div>

## Formats

| Format | Output |
| --- | --- |
| JSON | `report.json` with scan results |
| Static HTML | `index.html` with the dashboard in one file |
| OpenVEX | `openvex.json` with a VEX statement for each CVE on a shipped component |


## Static HTML dashboard

Each scan produces `index.html` with the dashboard and report data embedded. No template setup or external dependencies are needed.

Render it locally, or publish it as CI artifacts via GitHub Pages, Cloudflare Pages, S3:

```sh
trowl view ./trowl-report  # http://127.0.0.1:8765
```


## JSON report

`report.json` contains the same results shown in the dashboard. Read it in a text editor or process it with JSON tools and scripts. 

The top-level keys are:

| Key | Contents |
| --- | --- |
| `tool` | Trowl name and version |
| `image` | Path, detected format, file count and unpack notes |
| `summary` | Finding counts per check, ELF counts, scan time |
| `findings` | One entry per issue with `check`, `path`, `title`, `detail` and `evidence` |
| `binaries` | Hardening properties of every ELF file |
| `fstab` | Mount entries and missing flags |
| `kernel` | Config source, version, arch, baseline results, policy and modules |
| `sbom` | Components, presence status and the dependency graph. `null` without `--sbom` |
| `cves` | CVE rows with status, CVSS, KEV, EPSS, links, kernel assessment and any VEX file statement |
| `overview` | The AI summary if a model ran |

## OpenVEX output

`openvex.json` is an OpenVEX v0.2.0 document that Trivy, Grype and VulnScout can read. It holds one statement for each CVE on a component that ships in the image. The dashboard's CVE page has a download link for it.

Each statement names the component by its PURL, or by its CPE when it has no PURL. A component with neither is left out, and the report counts it under `cves.sources.openvex.unnamed`. Without an SBOM this applies to most package database entries, because Trowl only makes up a CPE from their names.

<div style={{ overflowX: 'auto' }}>

| Trowl status | OpenVEX status | Also written |
| --- | --- | --- |
| Affected | `affected` | `action_statement` with the fixed version when the CVE record gives one |
| Not affected | `not_affected` | `justification` from Trowl's kernel check or the SBOM's note, otherwise an `impact_statement` |
| Fixed | `fixed` | The SBOM's note in `status_notes` |
| Needs review<br/>Under investigation<br/>Unknown | `under_investigation` | Trowl's reason or the SBOM's note in `status_notes` |

</div>

A CVE covered by a [VEX file](../../features/cves-vex/#vex-files) keeps that file's statement as written. With `--override`, a statement that Trowl's kernel check replaced gets Trowl's status and a `status_notes` line that says what the file said.
